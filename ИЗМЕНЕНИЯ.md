## Как запустить

1. Скопируйте `config.example.py` в `config.py` и впишите свой пароль от MySQL.
2. Разверните базу (в таком порядке):
   - `sql/diary_therapy_bd.sql` — структура базы (у врачей появилось поле `photo`);
   - `sql/seed_data.sql` — тестовые данные (необязательно, но без них справочники пустые).

   Если база уже была развёрнута раньше, вместо пересоздания выполните
   `sql/migration_01_doctor_photo.sql` — он добавит поле `photo` к таблице врачей.
3. `pip install -r requirements.txt`, затем `python main.py`.

## Интерфейс

Все три окна переделаны в едином стиле (исходная синяя палитра проекта):

- разделы оформлены как вкладки-папки — выбранная «выдвигается» из папки;
- вместо таблиц — карточки с анимацией (появляются «лесенкой», приподнимаются при наведении);
- клик по карточке открывает выезжающую справа панель с подробностями;
- препараты нарисованы по форме выпуска (таблетка, капсула, ингалятор, флакон, тюбик);
- вместо смайликов — векторные иконки, нарисованные кодом.

**Администратор** — CRM клиники: аналитика (графики и PDF-отчёт как раньше), пациенты,
врачи с фотографиями (загрузка фото, редактирование профиля), учётные записи, журнал действий.

**Врач** — пациенты, назначения (выбор препарата плиткой, время приёма прямо в форме,
ход курса, завершение курса), дневники пациентов с графиком самочувствия, диагноз по МКБ-10
и комментарий пациенту. Врач может сам загрузить своё фото (клик по фото в шапке).

**Пациент** — «Сегодня» (приёмы лекарств по часам), дневник по шагам (настроение,
интенсивность, симптомы, триггеры, показатели, заметка), история с ответами врача,
назначения, профиль с карточкой лечащего врача. Формат записи дневника в базе прежний.

## Новые и изменённые файлы

- `windows/widgets.py` — общие виджеты: карточки, вкладки-папки, аватары/фото, иконки препаратов, боковая панель;
- `windows/common.py` — общие части окон врача и администратора/пациента (диалоги, карточки дневника и назначений);
- `windows/admin_window.py`, `doctor_window.py`, `patient_window.py` — окна переписаны;
- `db.py` — новые запросы для карточек, журнал действий, профиль врача с фото;
- фото врачей сохраняются в `images/doctors/` (уменьшаются до 600 px).

Формы из папок `ui/` и `ui_py/` (кроме окна входа) окнами больше не используются.

## Исправленные ошибки

- Генератор логина выдавал кириллицу («кузнецовдмитрий»), а проверка логина пропускает
  только латиницу — у администратора «Сгенерировать → Добавить» всегда заканчивалось ошибкой.
  Теперь логин транслитерируется (`kuznetsov_d`), а при совпадении получает номер.
- Расписание приёма привязывалось к назначению через `MAX(id)` — при одновременной работе
  двух врачей могло попасть к чужому назначению. Теперь `create_prescription` возвращает id новой записи.
- Дневник у врача делал по несколько запросов на каждую запись — теперь вся лента грузится тремя запросами.
- Пациента приветствовали по фамилии — теперь по имени.
- Таблица `audit_log` (журнал) и `doctor_comments` (комментарии врача) не использовались — теперь работают.
